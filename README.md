# Page Lens Reader — GPT + Kimi Chrome Side Panel

Page Lens turns the active web page into a guided reader. Read an article in sections, answer questions about its key ideas, then check the explanation against the source. It uses either a local CLIProxyAPI instance or a custom OpenAI-compatible API. CLIProxyAPI supplies an OpenAI-compatible endpoint backed by your Codex/ChatGPT and Kimi Code subscription logins.

## Guided reading

1. Open an article and open the extension side panel. The extracted text is immediately available to read.
2. Choose a model from **阅读模型**, then click **开始引导阅读** to generate questions. Short texts get 1–2 checkpoints; longer texts get 3–5. **取消生成** stops a slow request.
3. Scroll to the end of each section. A question appears automatically, testing the main idea, reasoning, or evidence. Questions and explanations are in Chinese; article text stays in its original language. Options are shuffled, so the answer position carries no hint. Press **A–D** to choose and **Enter** to submit.
4. Submit an answer to see feedback and a verbatim source quote. **在正文中定位** marks the exact quoted sentence in the article. Continue to unlock the next section, then review your results at the end, or use **换一组问题** for a fresh set.
5. Use **↗** to open a full reader tab with the article on the left and questions on the right. It reads from the original tab, which must remain open, and picks up the same reading progress.

**自由提问** keeps the original article chat available; replies render basic Markdown, and **■** stops a reply in progress. **Aa** changes text size. **重新读取** captures the current page again and resets reading progress if the article has changed. Questions and progress are saved per article in `chrome.storage.session`, so closing and reopening the panel resumes where you left off without generating again; Chrome clears them when it quits. Questions are generated by the selected model; quotes are checked against the corresponding section before any question is shown. If generation fails or the quote is invalid, the article remains readable and the generation button allows a retry.

## Local architecture

```text
Chrome side panel -> http://127.0.0.1:8317/v1 -> CLIProxyAPI -> Codex OAuth / Kimi OAuth
                  -> Custom API Base URL       -> Your API provider
```

The proxy is intentionally bound to `127.0.0.1`. Its management API is disabled. OAuth credential files live under `~/.cli-proxy-api`; the extension contains only a separate local client key.

## Load the extension

1. Open `chrome://extensions`.
2. Enable **Developer mode**.
3. Click **Load unpacked**.
4. Select the absolute `extension` folder in this project.
5. Pin **Page Lens Reader — GPT + Kimi**, open a normal web page, then click its toolbar icon.

After changing files, click **Reload** on the extension card in `chrome://extensions`.

## Add a custom API

1. Open the Page Lens settings from the gear button.
2. Under **自定义 OpenAI 兼容 API**, enter the Base URL, API Key, and exact model name.
3. Optionally click **测试并获取模型**. Providers without a `/models` endpoint can still be used by entering the model manually.
4. Save, then choose **自定义 API** in the side panel.

Custom providers must implement the OpenAI-compatible `POST /chat/completions` request format. Streaming SSE and non-streaming JSON responses are supported. Custom keys are saved in `chrome.storage.local`, not in this repository.

For a fresh clone that uses CLIProxyAPI, copy `extension/config.local.example.js` to `extension/config.local.js` and replace the local proxy client key. The real `config.local.js` is ignored by Git.

Run the dependency-free syntax, reader logic, and extraction checks with `npm test`.

`npm run test:ui` runs browser integration checks using mocked article/model responses, without sending article content to a live provider. It requires Playwright and a Chromium browser. Set `PLAYWRIGHT_MODULE` to the Playwright module path and, if needed, `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to a Chromium executable; the harness also recognizes the bundled Codex Playwright location.

## Useful commands

```bash
cliproxyapi -config ~/.cli-proxy-api/config.yaml -codex-login
cliproxyapi -config ~/.cli-proxy-api/config.yaml -kimi-login
launchctl kickstart -k gui/$(id -u)/com.local.pagelens.cliproxyapi
curl -H "Authorization: Bearer YOUR_LOCAL_KEY" http://127.0.0.1:8317/v1/models
```

To stop the local service:

```bash
launchctl bootout gui/$(id -u)/com.local.pagelens.cliproxyapi
```

## Privacy and quota behavior

- Nothing is scanned in the background. Page capture happens after you open the side panel or click **重新读取**.
- **开始引导阅读** sends the configured article excerpt once to generate the question set. Submitting choices, checking evidence, restarting the same set, and resuming saved progress are local actions. **换一组问题** sends the excerpt again.
- Generated questions, their source quotes, and your answers for up to 20 recent articles are kept in Chrome's in-memory session storage, never written to disk, and cleared when Chrome quits. Free-form chat sends the excerpt with the conversation. A 60,000-character cap is the default; lower it in settings to conserve quota or API credit.
- When a custom API is selected, page content is sent directly to its configured Base URL. Review that provider's privacy policy before use.
- Restricted browser pages such as `chrome://` cannot be read by Chrome extensions.
- Never publish `extension/config.local.js` or the runtime configuration. Both are excluded by `.gitignore`.
